# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build & Deploy

No build step. This is a pure static site — edit files directly and push to `main`. GitHub Pages auto-deploys to `https://theyuvrajgupta.github.io` within 1–3 minutes of each push.

There are no package managers, bundlers, linters, or test suites. There are also no JS libraries: GSAP was removed in v13 — everything is vanilla JS + CSS.

## Architecture

Three files do all the work:

- `index.html` — all content, markup, and section structure
- `portfolio/css/style.css` — all styles; no preprocessor
- `portfolio/js/script.js` — all interactivity; single `DOMContentLoaded` block

Assets (images, resume PDF) live in `portfolio/assets/`.

## Key JavaScript Patterns

**All code lives inside one `DOMContentLoaded` listener** in `script.js`. No modules, no libraries.

- **`body.js` gating** — JS adds `.js` to `<body>` first; all opacity-0 states (`.reveal`, hero entrance) only apply under `body.js`, so a script failure leaves the whole page visible. All field markup is static HTML, so no-JS still renders the full layered composition.
- **One master rAF loop** — cursor, hero parallax, and the field engine all register tasks in a single `rafTasks` loop. Never add a second `requestAnimationFrame` loop.
- **Cursor** — single dot that morphs into corner brackets over `a, button, [role="button"]`; only on `pointer: fine`, opt-in via `body.custom-cursor` (never `cursor: none` in plain CSS).
- **Depth parallax** — transforms all `[data-depth]` layers sitewide, grouped by hosting section/footer with a per-host IntersectionObserver gate so off-screen groups are never written (currently only the hero hosts layers; the engine is host-agnostic); skipped entirely under `prefers-reduced-motion`. If an interactive element ever gets depth, put `data-depth` on a wrapper and hover styles on the child — the engine owns the wrapper's `transform`. NOTE: floating interactive frags in the footer were tried and REJECTED (Yuvraj: "no floating ghosts here").
- **Field engine** — transforms all `[data-fz]` layers; runs only when `min-width: 993px` AND no reduced-motion; every write is epsilon-gated; geometry is cached and recomputed on debounced resize + window load; off-screen sections are skipped via a `rootMargin: 150px` IntersectionObserver. Zero layout reads inside the loop.
- **Modal pattern** — any `[data-modal-target]` (the cards' `.project-link` buttons AND competency proof chips) opens the matching modal. Enter/Space opens, Esc closes, Tab is trapped inside, focus returns to the trigger on close. Project cards are PLAIN containers (2026-07-28 red-team a11y fix): `role="button"` on the card made every descendant presentational and erased the h3s/copy from the accessibility tree, so the real control is the `.project-link` `<button>` (carrying a `.visually-hidden` project name) stretched over the whole card via its `::before` — never re-add `role="button"`/`tabindex` to the card itself. Card focus styles use `:has(.project-link:focus-visible)`.
- **Scrollspy + focal state** — ONE viewport-band `IntersectionObserver` (`rootMargin: '-40% 0px -55% 0px'`, not a ratio threshold — those break on sections taller than the viewport) drives both nav highlighting (sections/footer) and `.is-focal` toggling on `[data-focal]` targets (timeline items, ledger rows, `#featured-moment`). Focal visual states live under `@media (prefers-reduced-motion: no-preference)` + `body.js`, so reduced-motion and no-JS users get full static emphasis.
- **Chip → ghost focus pull** — delegated mouse/focus listeners on `.competency-grid` map a chip's `data-modal-target` to `#ghost-<id>` and toggle `.ghost-focus`.
- **Reveals** — `.reveal` + IO adds `.is-visible` (translateY + slight scale, deliberately NO blur); under reduced motion everything is made visible immediately.

## Gotchas

- Hero content must remain visible without JS — all entrance hiding is gated behind `body.js`.
- The custom cursor is enabled by JS adding `body.custom-cursor`; never put `cursor: none` in plain CSS.
- `prefers-reduced-motion` support is comprehensive (global animation kill + JS checks + focal states scoped under `no-preference`) — keep it that way when adding motion.
- Card grid centering uses `:nth-child(4)/(5)` rules that assume exactly 5 cards.
- **The content plane never moves**: never put `data-fz` on real copy, cards, the Summit strip, or anything interactive — decorative `aria-hidden` layers only.
- Never dim legible text as a "non-focused" state — focus is additive only; only aria-hidden mono decoration may rest de-emphasized (floor 0.6 opacity).
- No blur on reveals (deliberate cut: it trips the AI-design trend detector). Blur is static per depth tier only, never animated per frame.
- Sections use `overflow: clip` so field layers can bleed to the section edge without horizontal scroll; anything intentionally poking outside a section will be clipped.
- The scrollspy nav map skips `[data-focal]` items that aren't sections — if you add nav logic, keep the `matches('section, footer')` guard or timeline items will clear the nav highlight.
